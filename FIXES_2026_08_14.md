# 🐛 Bug Fixes - August 14, 2026

## Summary
Fixed 3 critical bugs affecting puzzle progress tracking, auto-snap functionality, and shuffle button.

---

## ✅ Bug #1: Progress Stuck at 1%

### Problem
Progress counter shows 1/12 (8%) even when puzzle is visually complete.

### Root Cause
- Server correctly calculates snap and sets `isPlaced: true` (socketServer.ts:240)
- Server broadcasts `piece:dropped` with `isPlaced` field (socketServer.ts:250-258)  
- **Client receives event but only applied x, y, rotation, z — ignored `isPlaced`**
- Progress calculation depends on `isPlaced` flag, so counter never updated

### Solution
**File:** `src/components/puzzle/PuzzleBoard.tsx` line 108

```typescript
onPieceDropped: (payload) => {
  puzzleState.applyRemote(payload.pieceId, {
    x: payload.x,
    y: payload.y,
    rotation: payload.rotation,
    isPlaced: payload.isPlaced, // ✅ ADDED - was missing
    z: payload.z,
    lockedBy: null,
  });
},
```

## ✅ Bug #2: Auto-Snap Not Working

### Problem
Pieces don't visually snap to correct position when dropped nearby.

### Root Cause
Same as Bug #1 - without `isPlaced` flag, piece stays at drop position instead of snapping to `correctX/correctY`.

### Solution
Same fix as Bug #1 - adding `isPlaced: payload.isPlaced` to `onPieceDropped` handler.

---

## ✅ Bug #3: Shuffle Button Not Working

### Problem
Clicking "Acak Ulang" button does nothing - pieces don't reshuffle.

### Root Cause
- Button calls `socket.resetRoom()` ✅
- Server receives request and emits `room:sync` with shuffled snapshot (socketServer.ts:347) ✅
- Socket listener exists (useRoomSocket.ts:208-210) ✅
- **But `onRoomSync` callback was NOT wired to PuzzleBoard - pieces never updated on client**

### Solution
**File:** `src/components/puzzle/PuzzleBoard.tsx` lines 87-90

```typescript
onRoomSync: (snapshot) => {
  console.log('[room:sync] Reshuffle received:', snapshot);
  puzzleState.applyStates(snapshot.pieces); // ✅ ADDED - was missing
},
```
